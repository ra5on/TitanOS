# Desktop-Modus (PLAN 61)

Seit 0.58.0 zeigt TitanOS am großen Bildschirm einen **Arbeitsplatz**: Programme liegen als Symbole auf einem Hintergrundbild, jedes öffnet sich in einem eigenen Fenster. Er ersetzt Kopfzeile, Seitenleiste und Statusleiste (Entscheidung des Projektinhabers vom 6.11.2026); deren Code ist seit 0.62.0 entfernt, der Arbeitsplatz ist die einzige Oberfläche. Am Handy und auf einem hochkant gehaltenen Tablet (unter 900 px Breite) gibt es stattdessen ein App-Raster; jedes Programm öffnet im Vollbild mit „Zurück“.

## Programme

Jede Seite von TitanOS gehört zu genau einem Programm (`web/src/lib/desktop/apps.ts`, ein Test prüft, dass keine Seite fehlt):

| Programm | Seiten |
|---|---|
| Dateien | Dateimanager, Einstellungen › Dateien |
| Freigaben | Freigaben, Dienste |
| Speicher | Speicher (Verwalten, Platten prüfen, Importieren, Platte ersetzen), Plattenwerkzeuge, Arbeitsspeicher |
| Docker | Container, Images, Volumes, Netzwerke, Aufräumen, HTTPS-Namen für Apps (PLAN 67: Bereiche links in der Leiste) |
| Virtuelle Maschinen | Maschinen, neue Maschine, ISO und Medien, VM übernehmen; darunter jede VM einzeln (seit 0.59.0 statt der Liste auf der Seite); jeder VM-Bildschirm als eigenes Fenster |
| Systemcontainer | LXC |
| App-Center | App-Katalog, eigene App, Plugins, Aufräumen |
| Sicherung | Datensicherung (alle Teile), Stick-Sicherung |
| KI-Agent | das Chatfenster des Agenten mit seinen eigenen Einstellungen |
| Monitor | Task-Manager, Verlauf, Aufgaben, Hardware prüfen, Hardware, Temperaturen |
| Protokolle | Systemprotokoll, Aktivität, Diagnosepaket |
| Aufgabenplaner | Skripte, Wartung, Energie-Zeitplan |
| Terminal | NAS-Shell (mehrere Fenster möglich) |
| Benutzer | Konten (Rolle, Apps, Freigaben, Kameras, Anmeldung), Zugang |
| Sicherheit | Firewall |
| Mein Konto | Passwort, 2FA, Passkeys, SSH-Schlüssel, WebDAV |
| Systemsteuerung | alle übrigen Einstellungen, Startseite „Übersicht“ (PLAN 71) |

Docker-Apps mit Weboberfläche (z. B. Immich) sind eigene Programme; ihr Fenster zeigt die App seit 0.61.0 immer in der **Fernansicht** (`docs/FERNANSICHT.md`): TitanOS öffnet sie auf dem NAS in einem eigenen Browser und überträgt Bild und Ton über die TitanOS-Adresse, also auch per Cloudflare, VPN und am Handy. „In eigenem Tab öffnen“ zeigt die App weiter direkt über ihren Namen bzw. Port. Normale Benutzer sehen nur die Programme ihrer Rolle und die Docker-Apps, die ihnen freigegeben sind (Benutzer › Programme).

## Fenster

- Eine Seite im Fenster läuft in einem Rahmen gleicher Herkunft (`X-Frame-Options: SAMEORIGIN`, `frame-ancestors 'self'`); fremde Seiten dürfen TitanOS weiter nicht einbetten. Im Rahmen zeigt die Seite keine Kopfzeile und keine eigene zweite Seitenleiste (`web/src/lib/desktop/frame.ts`, `inWindow`).
- Die Seitenleiste des Fensters listet die Seiten und Einstellungen des Programms; einklappbar (nur Symbole), je Programm gemerkt.
- **Systemsteuerung hat ein Menü (PLAN 71, „Variante C“; Gliederung seit PLAN 86, Inhaber 13.11.2026, Variante A und „Entwurf 1“):** die Seitenleiste. Oben das Konto mit seiner Rolle, darunter das Feld „Einstellung suchen“, dann „Übersicht“ und **acht Bereiche** in fester Reihenfolge, die Seiten darin in der Reihenfolge des bestätigten Entwurfs (in beiden Sprachen gleich, nicht A–Z): System (Über TitanOS, Updates, Darstellung, Datum und Uhrzeit, Dienste, Fernansicht) · Hardware und Energie (Hardware, Temperaturen, Energie, Ein-/Ausschalter, USV, Schreibcache) · Netzwerk und Fernzugriff (Netzwerk mit Tailscale/NetBird, WireGuard, Dynamisches DNS, Let's Encrypt, HTTPS-Namen für Apps) · Sicherheit und Konten (Benutzer, Zugang, Firewall, API und CLI) · Benachrichtigungen · Daten und Sicherung (Sicherungen, Systemdaten, Dateisuche) · Cluster · Smart Home und KI (Home Assistant, KI-Agent, MCP-Server) (`settingsGroups`/`settingsAreas` in `settings-search.ts`). **Ein Klick auf einen Bereich klappt seine Seiten direkt in der Spalte auf** (Akkordeon: ein Bereich offen zugleich, der Bereich der offenen Seite ist von selbst offen, Pfeil mit `aria-expanded`); eine Seite ist so zwei Klicks entfernt, die Spalte hat eine feste Breite (264 px, lange Namen brechen um). Ein Bereich, in dem das Konto nur eine Seite sieht (Benachrichtigungen, Cluster; für Benutzer auch Hardware und Energie usw.), öffnet sie direkt ohne Aufklappen. Tastatur: Enter/Leertaste klappt, ↑/↓ wandern, → klappt auf bzw. geht zur ersten Seite, ← klappt zu bzw. springt von einer Seite zu ihrem Bereich, Pos1/Ende. Eingeklappt (nur Symbole) öffnet ein Bereich seine erste Seite. Die frühere Bereichsseite gibt es nicht mehr: `/settings?area=<bereich>` (auch die alten Kennungen `accounts`, `services`, `ai`, `updates`, Menüleiste „Ansicht › Bereiche“, ⋯-Menü am Handy) öffnet im Fenster die erste Seite des Bereichs, die das Konto öffnen darf, und rollt „Alle Einstellungen“ am Handy zur Überschrift des Bereichs. Der Pfad über einer Seite nennt den Bereich als Text. **Die Suche findet jede einzelne Einstellung** (PLAN 86): Seiten, Reiter, Gruppen, Zeilen und Teile einer Zeile, auch die Zeilen von „Mein Konto“; ein Treffer zeigt den Ort darunter („Darstellung › Farben und Schrift › Sprache und Schrift“) und öffnet die Seite mit dem Reiter, klappt die Zeilen auf dem Weg auf, rollt zur Einstellung, markiert sie einige Sekunden (Ring in der Akzentfarbe); steht die Suche auf derselben Seite (Handy, eigener Tab), bekommt ihr Bedienelement die Tastatur, im Fenster bleibt sie in der Spalte. Rangfolge: Seiten, dann Einstellungen, deren Name mit dem Suchwort beginnt, dann Seiten, die nur über Stichwörter passen, dann der Rest. Der Index wird aus den Seiten erzeugt (`web/scripts/settings-index.mjs` → `settings-index.gen.ts`, `npm run settings-index`), Synonyme stehen in `settings-find.ts`; er lädt erst mit der ersten Suche. Pfeiltasten wählen, Enter öffnet, Escape leert. Eingeklappt steht dort nur die Lupe, ein Klick klappt auf und setzt den Cursor ins Feld; „Ablage › Einstellungen suchen“ tut dasselbe (Fensterbefehl `settings.search`). Benutzer sehen nur Bereiche, Seiten und Treffer, die sie öffnen dürfen; das gilt seit PLAN 86 auch für das ⋯-Menü am Handy. Der oberste Eintrag heißt „Übersicht“ (`/settings`): im Fenster Karten statt Kacheln – Zustand (Name, Version, Laufzeit, Volumes mit Text), Zu erledigen (Zustände der Einstellungen wie Update/USV/Zertifikat/Backup und offene Schritte der Einrichtungsliste von `/welcome`, gemeinsam in `lib/setup-checklist.ts`; leer „Nichts zu tun“), Dienste (Docker, VMs, LXC aus `/services`, SSH, Firewall; an/aus als Text, nur Administratoren) und Zuletzt geändert (nur Besitzer/Administratoren). SMB/NFS fehlen dort, weil es keine billige Abfrage gibt; „Häufig benutzt“ entfällt (keine Daten ohne neue Speicherung). Andere Programme behalten ihre Seitenleiste unverändert. Prüfung: `scripts/test-ui-settings-nav.mjs` (1280 px und Handy 390 px, Besitzer und Benutzer), `web/tests/settings-index.test.mjs`, `web/tests/ui-navigation.test.mjs`, `web/tests/lib/settings-jump.test.ts`.
- **Seitenleisten decken (PLAN 71):** Die Seitenleiste jedes Fensters (und die eigene Leiste von Dateien) ist undurchsichtig aus Theme-Variablen (`--surface` mit etwas `--bg`, leichter Verlauf als Glas-Anmutung); Symbole und Namen des Arbeitsplatzes scheinen nicht durch, auch nicht beim Verschieben.
- **Seiten mit eigener Leiste (seit 0.65.0, PLAN 69):** Ein Eintrag der Seitenleiste mit `page: true` (`apps.ts`, `pageDrawsSide()`) bekommt keine Fenster-Seitenleiste; die Seite zeichnet die eine Leiste selbst im gleichen Stil. Bisher nur Dateien › Durchsuchen: oben der Baum (Freigaben, für Administratoren Volumes mit Füllbalken, Stick, „Laufwerk formatieren …“), unten „Einstellungen von Dateien“ und „Seitenleiste einklappen“; kein zweites Menü im Inhalt. Das Einklappen bleibt die Einstellung des Fensters (Nachrichten `titanos-side-get`, `titanos-side-fold`, `titanos-side` in `frame.ts`). Auf `/settings/files` zeigt das Fenster wieder seine Leiste (Durchsuchen, Einstellungen). Unter etwa 760 px Fensterbreite gilt die Handy-Ansicht von Dateien.
- Beim Verschieben folgt das Fenster dem Zeiger per Transformation (eine Aktualisierung je Bild), der bewegte Hintergrund hält an; Lage und Größe werden erst beim Loslassen geschrieben.
- Größe an allen vier Ecken und Seiten, Doppelklick auf die Titelleiste = maximieren, an den Rand ziehen = halbe Seite, oben = Vollbild, Ecke = Viertel (mit Vorschau). Knöpfe rechts: in eigenem Tab öffnen, minimieren, maximieren, schließen.
- Unter 1280 px Breite öffnen Fenster maximiert.
- **Seiten als Fenster-Apps (PLAN 64, wie UGOS/DSM):** Die Titelleiste nennt Programm und Seite („Docker › Container“: der Eintrag der Seitenleiste für genau diese Seite, sonst der Titel der Seite). Die Seite zeigt im Fenster keine eigene große Überschrift (sie bleibt für Screenreader). Ihre Aktionen stehen in **einer Werkzeugleiste** direkt unter der Titelleiste (`PageHead`, Klasse `win-toolbar`): kompakt (32 px), oben fest, Hauptaktion rechts; was nicht passt, wandert in das Menü „⋯“ (nie abgeschnittene Knöpfe). Eine Seite ohne Aktionen hat keine leere Leiste; ihr Einleitungssatz steht dann oben. Inhalte als Karten (12 px Ecken, Kopfzeile mit Titel, 16 px Abstand), Einstellungen als Zeilen „Bezeichnung links, Wert rechts“ ab 640 px Fensterbreite, kompakte Tabellen. Das gilt nur im Fenster (`main.in-window`) und in der Vollbildansicht am Handy (`main.phone-page`, dort mit dem Seitennamen links in der Leiste, wenn er vom Programmnamen abweicht). Geprüft mit `scripts/test-ui-windows.mjs` (800/1100 px und Handy).
- **Designsprache aller Fenster (PLAN 67, Inhaber 7.11.2026, Vorbild Systemsteuerung › Netzwerk):** links in der Seitenleiste die Bereiche des Programms, oben Reiter nur für Unterteile einer Seite, darunter Karten (`.tile.ui-card` in `app.css`) mit Kopfzeile (`.card-head`: Titel, eigene Knöpfe rechts), Zeilen „Bezeichnung (+ Hinweis) links, Bedienelement rechts“ (`.set-row`, `.set-label`, `.set-hint`, `.set-control`), Fußzeile für die Aktionen der Karte (`.card-foot`) und Hinweiskarten mit einer Aktion (`.banner`). Einstellungsseiten haben keine lose Knopfleiste über dem Inhalt; Listen (Container, Dateien, Benutzer, VMs, Freigaben) behalten eine schlanke Werkzeugleiste: Suche/Filter links, **eine** Hauptaktion rechts, der Rest in „⋯“. 16 px zwischen den Karten (die Seite im Fenster ist eine Spalte mit `gap`), 11–12 px Zeilenabstand, Schalter `input.switch`, kompakte Auswahl (Segmente, kleine Vorschaubilder) statt großer Kacheln. Unter 640 px Fensterbreite stehen Bezeichnung und Bedienelement untereinander (ein einzelner Knopf/Schalter bleibt rechts). Systemsteuerung öffnet bei genug Platz mindestens 1180 × 830 px. Geprüft mit `scripts/test-ui-windows.mjs` (`WINDOWS_ALL=1`, 800/1100 px und Handy 390 px).
- Die Adresse des Browsers zeigt die Seite des Fensters vorn; ein Lesezeichen oder Link öffnet das passende Programm. Der Verlauf wächst dabei nicht (Zurück bleibt auf dem Arbeitsplatz).
- Tastatur: Alt + Q Fensterwechsler (Alt + Tab gehört dem Betriebssystem), Alt + Pfeile andocken, Alt + W schließen, Alt + M minimieren, Alt + K Arbeitsplatz zeigen (seit 0.64.0; Alt + D gehört der Adresszeile des Browsers), Strg + Leertaste Menü, Alt allein oder F10 Menüleiste. Die Tasten wirken auch, wenn eine Seite im Fenster den Fokus hat; Alt und F10 bleiben bei einem VM-Bildschirm, der Fernansicht und im Terminal dort (z. B. für mc).

## Arbeitsplatz

- **Menü (seit 0.77, PLAN 79-10/79-11, Entwurf `Entwuerfe/79-menue/v2-*.png`):** Es gibt genau ein Menü, es heißt „Menü“ (`Launcher.svelte`). Der Knopf „Menü“ (Raster-Symbol und Wort) sitzt immer ganz links in der oberen Leiste, der Menü-Knopf im Dock bleibt und öffnet dasselbe, gleich aufgebaute Menü (oben unter der Leiste bzw. am Dock). Aufbau: Filter (Alle, TitanOS, Docker-Apps, VMs, Zuletzt), rechts daneben die geltende Reihenfolge („Sortiert A–Z“ oder „Eigene Reihenfolge“), die Programme, unten zwei Zeilen gleich großer Knöpfe – oben Konto (kleines Kürzelbild und Name, öffnet „Mein Konto“), Systemsteuerung, Updates (mit Anzahl), App-Center; unten fest Abmelden, Neustart, Herunterfahren (seit 0.80 ohne „Sperren“, PLAN 84-3). Rollen wie bisher: Benutzer sehen Updates, App-Center, Neustart und Herunterfahren nicht. „Über TitanOS“ steht nicht im Menü (Systemsteuerung › Über). **Kein eigenes Suchfeld im Menü:** die Suche sitzt in der oberen Leiste direkt neben dem Knopf; beim Öffnen des Menüs (auch vom Dock, auch mit Strg + Leertaste) bekommt dieses Feld die Tastatur, Tippen filtert also wie bisher Programme, Seiten und Schnellaktionen, Enter öffnet den ersten Treffer, Pfeil runter geht in die Programme, Pfeil hoch aus der ersten Zeile zurück ins Feld. **Reihenfolge:** ab Werk A–Z (nach Namen in der Sprache der Oberfläche); der Benutzer zieht Programme im Menü an eine andere Stelle (Strich zeigt den Platz), oder schaltet „Anordnen“ ein (Pfeilknöpfe unter jedem Programm, auch am Handy) oder drückt Strg + Umschalt + Pfeil links/rechts auf einem Programm; der neue Platz wird angesagt. Gespeichert je Konto (`menuOrder` in der Einstellung `desktop`; leer = A–Z, unbekannte neue Programme folgen A–Z), „Wieder A–Z sortieren“ setzt zurück. In „Zuletzt“ und während der Suche wird nicht umsortiert. Ein Programm aus dem Menü hinaus auf den Arbeitsplatz oder ins Dock ziehen legt es dort ab (das Menü tritt zur Seite, sobald der Zeiger es verlässt). Der Dialog für Neustart/Herunterfahren gehört dem Arbeitsplatz, nicht dem Menü, und bleibt deshalb stehen, während das NAS vorbereitet.
- **Obere Leiste (seit 0.64.0, PLAN 67 Variante B; Inhalt seit 0.77 nach PLAN 79-10):** eine durchgehende Leiste in Glas mit Linie darunter. Links der Knopf „Menü“, daneben das kleine Suchfeld (Lupe und „Suchen“, ohne Kürzeltext; es ist das Suchfeld des Menüs), dann der Name des Programms vorn (fett, immer ganz gezeigt) und dessen **Menüleiste**, im Cluster dahinter der Umschalter zwischen den Nodes; rechts laufende Aufgaben (Abzeichen), die Glocke (Mitteilungen), **CPU und RAM zusammen in einem kleinen Rahmen im Aussehen des Suchfelds** und Datum/Uhrzeit (unter 1100 px nur die Uhrzeit). CPU/RAM lässt sich je Konto aus- und einblenden (`barLoad`, ab Werk an): Systemsteuerung › Darstellung › Dock › „Obere Leiste“, Menü „Ansicht“ des Arbeitsplatzes und Rechtsklick auf die Leiste; unter 1280 px blendet die Leiste es aus. Unter 1180 px zeigt der Menü-Knopf nur sein Symbol (Name als Tooltip und für Screenreader) und das Suchfeld ist so breit wie sein Wort, damit alle Menüs des Programms ganz bleiben. **Entfallen sind** das TitanOS-Logo-Menü, die Schnelleinstellungen und das Konto-Kürzel: ihre Einträge stehen im Menü; die Schnelleinstellungen boten Hell/Dunkel (Darstellung › Farben), Bewegter Hintergrund (Darstellung › Hintergrund › „Hintergrund wählen“), Aufgaben und Task-Manager (Programm Monitor, Abzeichen in der Leiste), die Mitteilungsliste mit „Alle gelesen“ (Glocke) und „Mitteilungen einstellen“ (Systemsteuerung › Benachrichtigungen, Link in der Glocke). Die Sprache, bisher nur im Konto-Menü, steht seit PLAN 86 mit der Schriftgröße in der Gruppe „Sprache und Schrift“ unter Darstellung › Farben und Schrift. Offene Fenster stehen nur im Dock. Rechtsklick auf die Leiste stellt ihre Größe ein (Klein 34 px, Mittel 40 px, Groß 48 px); Fenster und Andocken beginnen unter ihr. Das Menü schließt bei einem Klick daneben (auch in ein Fenster).
- **Menüleiste je Programm** (PLAN 67-1, Beschreibung in `web/src/lib/desktop/menubar/menus.ts`): jedes Programm hat seine Menüs (z. B. Dateien: Ablage, Bearbeiten, Ansicht, Gehe zu), dazu überall **Fenster** (Minimieren, Maximieren, Links/Rechts andocken, Alle Fenster dieses Programms, Arbeitsplatz zeigen, In eigenem Tab öffnen, Schließen) und **Hilfe** (Hilfe zu <Programm> → Dokumentation, Tastenkürzel, Diagnose). Ohne Fenster vorn: Ablage (Ordner anlegen, Hintergrund) und Ansicht (Symbole ordnen, Symbolgröße, Widgets, Dock). Menüs öffnen per Klick und wechseln beim Überfahren, solange eins offen ist; Tastatur: Alt oder F10, Pfeile, Enter, Esc. Einträge zeigen ihr Tastenkürzel (nur Kürzel, die wirklich wirken), Häkchen und Untermenüs; Einträge, die das Konto nicht darf, fehlen. Befehle einer Seite meldet die Seite selbst an (`web/src/lib/menu-commands.svelte.ts`); über die Fensterbrücke gehen nur Kennungen und Zustände (`titanos-menu`, zurück `titanos-menu-action`, geprüft auf Herkunft und Rahmen, nur Kennungen, die das Programm kennt). Listen-Untermenüs (z. B. Dateien › Gehe zu › Freigaben, Öffnen mit, VMs › Tasten senden, Fernansicht › Heruntergeladen) füllt die Seite selbst mit reinem Text (höchstens 40 Einträge). Ein Eintrag ist nur abgeschaltet, solange er gerade nicht geht (z. B. Umbenennen ohne gewählte Datei); Einträge ohne Gegenstück in der Oberfläche stehen nicht im Menü (ein Test prüft, dass jeder Seitenbefehl von einer Seite angemeldet wird). Am Handy stehen dieselben Einträge im ⋯-Menü der Programmleiste.
- **Dock** (seit 0.59.0, ab Werk an): angeheftete Programme und offene Fenster (nach einem Strich), Punkt = offen, Vergrößern beim Überfahren. Ziehen aus dem Menü oder vom Arbeitsplatz heftet an, Ziehen im Dock sortiert um. Rechtsklick auf das Dock: Dock bearbeiten (Größe, Deckkraft, Vergrößern Aus/Leicht/Stark, Position unten/links/rechts, × entfernt), Position, Dock ausblenden. Rechtsklick auf ein Symbol im Dock: das Programm-Menü mit „Im Dock behalten“/„Aus dem Dock entfernen“. Mehr Platz bietet Systemsteuerung › Darstellung, Reiter „Dock“ (PLAN 64/67; die alte Adresse `/settings/appearance/dock` führt dorthin) mit denselben Einstellungen, der Liste der angehefteten Programme und einer Vorschau. Angedockte Fenster und Symbole halten den Platz des Docks frei.
- **Menü-Knopf im Dock** (seit 0.65.0, PLAN 69, Inhaber: links am Anfang; heißt seit 0.77 „Menü“): Raster-Symbol vor den angehefteten Programmen, abgetrennt durch einen Strich; öffnet das Menü direkt am Dock (unten: darüber, links/rechts: daneben). Der Knopf der oberen Leiste und Strg + Leertaste öffnen es oben. Die Leiste „Widgets bearbeiten“ sitzt über dem Dock (Abstand `wm.inset`), nicht mehr dahinter.
- **Symbole:** frei auf einem unsichtbaren Raster (ziehen an eine freie Stelle; auf ein anderes Symbol = tauschen, auf einen Ordner = hinein), „Automatisch anordnen“ im Rechtsklick; sonst ordnen nach Art, Name oder zuletzt benutzt; drei Größen; Ordner; Abzeichen (Zahl = Updates, ! = Warnung, Punkt = läuft/gestoppt, Text beim Überfahren). Rechtsklick auf ein Symbol bzw. den Arbeitsplatz für alle Aktionen.
- **Widgets** frei auf einem Raster von 20 px; Rechtsklick auf ein Widget: Größe, Entfernen, Bearbeiten, Hinzufügen, alle ausblenden (wieder einblenden im Rechtsklick auf den Arbeitsplatz); an der Ecke vergrößern, Galerie mit Zustand, CPU/RAM, Netzwerk, Volumes, Docker-Apps, VMs, Sicherungen, Temperaturen, Uhr, Home Assistant, Aufgaben, iGPU, NPU, Grafikkarte und Kamera. Sie lesen nur, was die Oberfläche ohnehin abfragt, und wecken keine Platten.
- **Widgets iGPU, NPU, Grafikkarte (seit 0.77, PLAN 79-5, Entwurf `Entwuerfe/79-widgets/entwurf.png`):** drei eigene Widget-Arten, die Art des Widgets ist die Art des Geräts (`igpu`/`npu`/`gpu`). Die Werte stehen in `accelerators` der Systemdaten (`GET /api/v1/system`, jedes angemeldete Konto), die der Arbeitsplatz ohnehin abfragt – keine eigene Abfrage. Aufbau: Titel nach Art, darunter der Gerätename, Auslastung in Prozent mit Verlaufslinie, Kacheln für Temperatur, Grafikspeicher (mit Balken), Leistung und Takt. **Ein Wert, den das Gerät nicht meldet (`null`), bekommt keine Kachel – nie 0, nie „nicht gemeldet“**; ein gemeldeter Wert 0 wird gezeigt, Lücken im Verlauf unterbrechen die Linie. Im Rechtsklick-Menü des Widgets: ein Haken je Wert (Auslastung, Verlauf, Temperatur, Grafikspeicher, Leistung, Takt; das Menü bleibt dabei offen) und bei mehreren Geräten der Art die Wahl des Geräts; beides wird mit dem Widget gespeichert (`hide`, `device` = PCI-Adresse; ohne Wahl das erste Gerät). „Widget hinzufügen“ bietet nur Arten an, für die dieses NAS ein Gerät hat. Ein Widget, dessen Gerät fehlt, zeigt „Kein solches Gerät gefunden.“ Grenze: die Engines (z. B. Video) zeigt das Widget nicht.
- **Programm „NVR“ und Widget „Kamera“ (0.78, PLAN 79-7, Entwürfe `Entwuerfe/79-nvr/live2.png`, `entwurf.png`):** Das Programm NVR (eigenes Symbol: Kamera mit Aufnahme-Punkt) steht für jedes Konto im Menü; seine Seitenleiste nennt Live, Aufnahmen, Ereignisse und für Besitzer/Administratoren Kameras, Einstellungen, Diagnose. Ein Konto mit der Rolle Benutzer sieht nur die Seiten, für die es ein Kamerarecht hat (Live nur mit „Live ansehen“, Aufnahmen und Ereignisse nur mit „Aufnahmen ansehen“ bei mindestens einer Kamera; `lib/nvr/side.svelte.ts`, abgefragt höchstens einmal je Minute über `GET /api/v1/nvr/cameras`); dieselbe Regel gilt für die Menüleiste und das ⋯-Menü am Handy. Das Einklappen der Seitenleiste bleibt wie bei jedem Programm gespeichert (`folded`). Die Anordnung der Live-Kacheln, die eigene Reihenfolge am Handy und die Schalter des Menüs „Ansicht“ stehen je Konto in `desktop.nvr` (`lib/nvr/layout.ts`, im Fenster über die Nachrichten `titanos-nvr-get`/`-set` an den Arbeitsplatz, der allein schreibt). Das Widget „Kamera“ zeigt eine gewählte Kamera (Rechtsklick: Kamera wählen; gespeichert als `camera`), klein als Standbild alle fünf Sekunden, groß als Live-Bild; ein Klick öffnet den NVR mit dieser Kamera groß (`/nvr?camera=<id>`). Es bietet nur Kameras an, die das Konto live sehen darf. Am Handy gibt es keine Widgets, also auch dieses nicht. Prüfung: `scripts/test-ui-nvr.mjs` (1280 px, mit Seiten im Fenster) und `scripts/test-ui-nvr-phone.mjs` (390 px).
- **Hintergrund:** zwölf eigene Bilder (sechs gezeichnete als SVG, hell und dunkel nach Theme, und sechs Fotos der Anmeldeseite) oder ein eigenes Bild (wie der bisherige Hintergrund je Konto auf dem Stick, höchstens 10 MB). „Bewegter Hintergrund“ verschiebt es langsam und färbt es nach Tageszeit; bei „Bewegung reduzieren“ steht es still.
- **Sperrbildschirm** (Strg + Alt + L, automatisch nach einstellbarer Zeit; seit 0.80 kein Knopf im Menü). Das Mitteilungs-Center als eigene Fläche gibt es seit 0.77 nicht mehr; Mitteilungen stehen in der Glocke der oberen Leiste.
- Dateien vom PC auf den Arbeitsplatz ziehen öffnet „Dateien“ und lädt sie in den gerade offenen Ordner hoch (mit der üblichen Rückfrage).

## Gespeichert

- Je Konto in der Einstellung `desktop` auf dem Stick (`/config/users/<name>/desktop.json`): Symbole mit ihren Plätzen, Ordner, Widgets (und ob ausgeblendet), Dock, Größe der Leisten, CPU/RAM in der Leiste, Reihenfolge der Programme im Menü, Hintergrund, Sortierung, Sperrzeit, eingeklappte Seitenleisten, gespeicherte Fenster-Anordnungen. Geschrieben wird nur nach einer Änderung, 1,5 s nach der letzten.
- Offene Fenster mit Lage und Größe nur im Browser (`localStorage`): sie ändern sich ständig und sollen den Stick nicht abnutzen.

## Handy (PLAN 64)

- Startbildschirm: Suchleiste unter der Statusleiste und beim Blättern oben haftend, Ränder für Notch und Home-Leiste auf allen Seiten, nichts breiter als der Bildschirm, Eingabefelder mindestens 16 px (kein Zoom in Safari); beim Öffnen beginnt er oben. Im Cluster steht der Node-Umschalter neben der Suche (44-px-Ziele, Menü über die ganze Breite); verwaltet die Seite einen anderen Node, nennt ihn die Leiste über dem Programm.
- Docker-Apps erscheinen auch, wenn ihre Adresse für den Browser nicht nutzbar ist (z. B. Vorlage `http://[IP]:8080`): die Fernansicht braucht nur den Namen. Sie öffnen im Vollbild; Zurück führt zum Raster.
- Ursache der oben abgeschnittenen Suchleiste war eine fremde, allgemeine Klasse `.bar` (Fortschrittsbalken, 6 px hoch) auf der Kopfzeile des Startbildschirms. Prüfung: `scripts/test-ui-phone.mjs` (Emulation 390×844 und 430×932, kein echtes iPhone).

## Grenzen

- Seiten im Fenster sind eigene Rahmen; jedes offene Fenster lädt die Oberfläche einmal (mehr Arbeitsspeicher im Browser).
- Die Fernansicht braucht einen Browser mit WebCodecs (aktuelle Chrome/Edge, Firefox ab 130, Safari ab 16.4) und HTTPS oder `localhost`; sonst erklärt das Fenster es und bietet „In eigenem Tab öffnen“. Grenzen der Fernansicht (Apps im Host-Netz, Speicher je Ansicht) in `docs/FERNANSICHT.md`.
- Seit 0.63.0 gibt es drei Arten von App-Fenstern: **Web-App direkt** (Craft-Programme laufen im Browser, `docs/WEBAPPS.md`), Fernansicht für Docker-Apps, TitanOS-Seiten. Kein App-Fenster zeigt eine Adresse; Lautstärke, Dateien, Zwischenablage, Qualität und „In eigenem Tab öffnen“ stecken im ⋯-Menü der Titelleiste und seit 0.64.0 auch in der Menüleiste (Ablage, Bearbeiten, Ansicht, App).
- Beim Verschieben eines Symbols erscheint das Raster aller Plätze bis zum Dock; der Zielplatz (bzw. das Symbol, mit dem getauscht wird) ist hervorgehoben, das Symbol bleibt in voller Größe. Die Reihen sind gleichmäßig gestreckt, die gespeicherten Plätze ändern sich dadurch nicht.
- **Schnellaktionen im Menü** (seit 0.66.0, PLAN 70, `quick-actions.ts`; seit 0.77 getippt in das Suchfeld der oberen Leiste): Beim Tippen zeigt das Menü unter „Aktionen“ auch Dinge zum Tun, gefunden über alle Wörter der Suche: NAS-Sitzung sperren, Abmelden (Rückfrage); für Besitzer/Administratoren außerdem Container neu starten/stoppen (Rückfrage) bzw. starten, VM herunterfahren (Rückfrage) bzw. starten, „Sicherung jetzt starten“ je eingeschaltetem Auftrag (die Aufträge werden erst beim Tippen geladen), „Stick jetzt sichern“, „NAS neu starten …“/„Herunterfahren …“ (der bekannte Dialog). Dieselben Routen wie die Seiten (`/docker/containers/<id>/<aktion>`, `/vms/<name>/<aktion>`, `/backups/<id>/run`, `/config-backup/run`); das NAS prüft die Rechte. Die Rückfrage ist ein einfacher Dialog, „Abbrechen“ hat den Fokus, Enter löst nie die Aktion aus. Ergebnis als Zeile im Menü („Ausgelöst: …“ bzw. Fehlertext). Am Handy gibt es sie seit 0.77 im Menü (Suche oben neben dem Knopf „Menü“); das App-Raster selbst filtert nur Programme.
